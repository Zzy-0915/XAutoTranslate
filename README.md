# XAutoTranslate v9 · 快速翻译 / 双指长按日志

适用 X 12.33（31）、iOS 17.2+、arm64。移除旧版 XAutoTranslate，彻底退出 X，再通过 JailFools 注入本次 dylib。使用 Apple iPhoneOS SDK 编译、ad-hoc 签名。

## 本次仅调整触发方式

取消 v8 的停稳约 1 秒门槛与滚动暂停判断。帖子/评论有足够区域进入可见范围后即进入翻译队列，拖动和惯性滚动时也可触发；每 250ms 检查可见内容。没有人为停留延迟，实际网络启动仍受队列和既有间隔控制。

请求并发和间隔保持 v8：官方、Google 各最多一条在途请求，官方启动至少间隔 1.5 秒，Google 至少间隔 1 秒。离屏尚未开始的任务仍移出队列，后台和弹窗覆盖时不启动新任务。不添加额外的额度消耗循环或重复翻译；请在 X 内正常浏览不同内容测试双通道。

移除界面上的日志悬浮按钮。用两根手指同时在 X 窗口内按住约 2 秒打开原有日志面板，仍包含实时日志和导出日志。手势附加到正常应用窗口，新窗口和场景变化时自动补挂；允许同时识别原生手势，不取消或延迟视图触摸。手指移动超过约 18 点会取消本次长按，面板已打开时不重复弹出。日志文件持续记录，XAD_DIAGNOSTICS=0 可在编译时移除诊断模块。

## 保留 v8 逻辑

保留崩溃修复：通过 T1PostTranslationHelper.getOrCreateInfoFor: 取得原生翻译状态，禁止调用会触发 Swift 断点的 T1PostTranslationInfo 默认初始化入口。使用 X 原生译文、提示、服务商和显示原文路径，不增加正文前缀或覆盖浮层。

官方优先。只有识别到官方原生 state=2（翻译失败/重试状态）才启用 Google；单纯慢、超时、排队、路由不可用或无效结果都不启用 Google。30 秒仍无明确失败时暂缓该内容。官方实际失败后暂停 5 分钟，期间对可见内容使用 Google；到期单条探测官方恢复，连续失败延长暂停，最长 15 分钟。state=2 代表翻译失败，不一定是 HTTP 429；不把错误码 60 自动当成 429。

成功完整译文继续使用进程内缓存，键包括推文 ID、原文和目标语言；重复浏览不再次请求。中文和无语言内容跳过，空结果、流式片段、原文不标记成功。退出进程清空缓存。长期内存占用随实际成功文本增加。

Google 补位使用 HTTPS translate.googleapis.com/translate_a/single（client=gtx、sl=auto、tl=zh-CN），将待翻译原文发送给 Google，不发送 X 登录令牌或 Cookie。GTX 仍可能限流或不可用，保留 Retry-After 与退避保护。双通道都不可用时保留原文。

## 构建验证

bash scripts/build-ios.sh。GitHub Actions 运行原生工厂崩溃回归、可见内容无停留排队、官方实际失败后补位、超时不切换、原生 UI 模型及缓存/请求控制测试，再构建带日志和无日志版本，检查签名与 Mach-O。二进制检查确认不包含旧悬浮按钮入口，诊断版含双指长按配置入口。build-info.txt 记录提交、工具链和哈希。模拟测试及编译不代替手机上的手势与显示效果验证。
