# XAutoTranslate v8 · 停留触发 / 闪退修复

适用 X 12.33（31）、iOS 17.2+、arm64。先移除 v7 及其他旧版 XAutoTranslate，彻底退出 X，再通过 JailFools 注入本次 dylib。使用 Apple iPhoneOS SDK 编译并进行 ad-hoc 签名。

## 闪退原因与修复

用户提供的两份崩溃报告均为主线程 EXC_BREAKPOINT / SIGTRAP，调用链为 Refresh → XATNativePublish → T1Twitter + 0x7b239c。对应 X 12.33 的 T1PostTranslationInfo.init，内部调用 __swift_stdlib_reportUnimplementedInitializer 后执行 brk。报告不是内存不足终止；不能把这次闪退归因于译文缓存。

本次删除对该类型默认 init/new 的调用，改用 X 已核对的 T1PostTranslationHelper.getOrCreateInfoFor: 工厂创建/取得状态。保留 X 原生译文模型、服务商提示和显示原文功能，不添加正文前缀或覆盖浮层。不再额外执行 UITableView beginUpdates/endUpdates 强制整表重排，只通过 X 原生动态内容通知刷新。模拟测试把默认 init 设为禁止入口，确保发布必须通过工厂。

## 只翻译停留内容

帖子/评论须有足够区域可见，连续稳定约 1 秒，且父级滚动视图没有拖动、惯性滑动或触摸跟踪，才进入翻译队列。视图位置继续变化或单元被复用会重新计时，离屏清零；弹窗覆盖时暂停新任务。每 250ms 检查一次，因此实际触发通常在稳定 1～1.25 秒后。快速划过不提交翻译。

官方与 Google 各最多一条在途请求，官方两次启动至少间隔 1.5 秒，Google 至少间隔 1 秒。未开始、失去停留资格的任务移出队列；网络完成和退避定时器也受同一资格门槛约束，不能在用户继续快速滑动时偷偷启动下一条。已经提交的请求允许结束并缓存，官方请求没有已核对的安全取消接口；Google 长文本离屏后不再继续未开始的分段。

每次真正启动 Google 请求前还会实时复核前台、可见和稳定状态，避免两次轮询之间开始滚动或切入后台后，旧的资格快照继续启动请求。

## Google 启用条件

严格先使用官方通道。只有观察到官方原生翻译状态 state=2（对应“翻译失败/重试”状态）时，才启用 Google。该状态证明官方翻译失败，未必能证明 HTTP 429，日志不会把错误码 60 擅自标为 429。

单纯等待 8 秒、排队、路由不可用、结果未通过验证，都不启用 Google；等待 30 秒仍无明确失败时暂缓该内容并记录日志。官方真实失败后暂停官方 5 分钟，期间仅对满足停留条件的新内容使用 Google；到期只用一条新内容探测官方，恢复成功则回到官方优先，连续失败延长暂停，最长 15 分钟。识别的是原生失败状态，不要求用户再手点“重试”，也不人为延迟到屏幕绘制一帧错误提示。

## 缓存、网络和日志

通过验证的完整译文继续使用进程内缓存，键包括推文 ID、原文及目标语言。滚动重访不重复请求，退出进程清空。中文及无语言内容跳过，流式片段、空结果、仅返回原文的结果不写入成功缓存。缓存仍随实际成功文本增长；本次主要减少无效翻译、在途对象和刷新频率，没有通过清空成功缓存掩盖初始化崩溃。

Google 补位使用 HTTPS translate.googleapis.com/translate_a/single（client=gtx、sl=auto、tl=zh-CN），会将待翻译原文发送给 Google，不发送 X 登录令牌或 Cookie。GTX 没有免限流承诺，可能返回 429 或不可用；遵守 Retry-After 并退避。两个通道都不可用时保留原文。

保留“日志”按钮、实时日志和导出日志。DWELL 记录停留资格；ROUTER 记录官方 state=2 确认、启用 Google 和暂缓原因；RENDER 记录模型文字核验和动态通知，不代表像素截图验证。日志不记录正文、完整请求 URL 或账号令牌。XAD_DIAGNOSTICS=0 可移除诊断模块。

## 构建验证

bash scripts/build-ios.sh。GitHub Actions 先运行模拟原生工厂、停留/滚动/复用、离屏队列、网络完成时暂停、官方真实失败后补位、超时不补位、原生译文和缓存的测试，再分别构建带日志/无日志版本，检查 Mach-O、初始化入口及签名页哈希。build-info.txt 记录提交、工具链和 SHA-256。测试与静态定位不替代手机实测，仍需验证持续滚动与原生显示稳定性。
