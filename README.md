# XAutoTranslate

iOS 原生 X 自动翻译插件。当前修复针对 X 12.33 上“进入帖子才自动翻译，首页不触发”的问题，继续调用 X 自带翻译，不新增第三方翻译请求。

## 构建

GitHub Actions 和 Makefile 统一编译根目录 `Tweak.m`，模型辅助代码在 `XATModelSupport.h`。`Tweak.x` 仅保留迁移说明。不要再把源码写入 workflow 的 heredoc。

1. 将修改放到仓库后，在 Actions 中运行 **Build JailFools Dylib (Exact Native Hook)**；main/master 的 push 和对应 PR 也会自动构建。
2. 下载 `XAutoTranslate-JailFools` artifact，解压得到 `XAutoTranslate.dylib`。
3. 用原来的注入方式替换旧 dylib，避免同时加载新旧版本；彻底关闭 X 后重新打开。

Actions 使用 macOS 编译 arm64/iOS 15+ 动态库并进行 ad-hoc 签名。本 workflow 不生成 `.deb`。它先运行 Foundation 模型回归测试，再编译 iPhone 动态库。

## 本次修改

- 原来只有翻译按钮适配器绑定时才触发。现在会寻找实际存在且方法签名匹配的帖子正文适配器，在正文可见后尝试原生翻译入口；另为暴露 `viewModel` 的 `T1StatusView` 提供入口。
- 每 0.5 秒检查已经绑定的弱引用视图，包括先预加载、后滚动进屏幕的帖子。等待控制器/账号等条件时每 2 秒再检查，尚未准备好不会永久标记为已处理。
- 延迟执行前验证视图仍对应同一模型，排除已离屏、已复用、译文、错误和引用正文适配器。
- 保留可用的原生翻译按钮回调；没有按钮时才尝试签名验证后的原生引擎。一次提交只选一个入口，不因缺少同步事件回调而连续 toggle。
- 从包装模型中获取真实帖子 ID；无法获取时按模型对象生命周期去重，不把内存地址当成帖子 ID。共享底层 status 的包装模型使用同一提交记录。
- 记录正文绑定、原生提交、译文模型和译文视图显示，区分“触发”与“显示”。菜单数量表示提交次数，不代表成功次数。

## 真机验收

编译和模型测试不能证明 X 私有视图布局兼容。尚需 X 12.33 真机测试：

1. 冷启动后只停留首页，缓慢滚动英文/日文帖子，不先进入详情，检查译文是否在首页出现。
2. 快速滚动再返回，确认没有串帖、重复切回原文；再进入详情，确认原有翻译仍可用。
3. 暂停后滚动应不自动提交；重新开启应处理当前可见帖子；中文帖子应跳过。
4. 若首页仍不显示，导出日志，保留 `[时间线入口扫描]`、`[正文绑定]`、`[等待原生入口]`、`[自动提交]`、`[译文模型检查]`、`[译文视图绑定]` 和原生错误行。

`[自动提交]` 只证明调用了入口；`translatedModel=YES` 只证明适配器提供了译文模型；`visible=YES` 表示译文视图位于可见区域，最终文字需肉眼确认。日志中的原生状态数字没有经过枚举定义验证，不据此判定成功。

若首页根本不创建译文正文适配器，仅放宽 `shouldBeVisibleForViewModel:` 不能创建缺失的区域，需要根据新日志/对应版本视图结构继续适配。为避免未知异步结果导致重复 toggle，已经提交过的模型不会自动重试请求；原生错误后可在菜单清除记录再试。
